# XrayUI 代理控制与服务器详情布局优化方案

## 1. 事实基线

- 控制面板中的全局代理、TUN、路由状态和完全退出目前位于同一行，但整行右对齐，路由状态排在全局代理和 TUN 之后。
- 服务器列表项右上角目前可能同时显示主代理按钮与辅代理按钮；端口标记与操作按钮混在同一区域，测试延迟显示在第二行的右侧。
- 服务器详情卡片位于可滚动区域中；其边框会随父区域拉伸，在内容未溢出时仍留下较大的卡片底部空白。
- 已有主代理/辅代理的运行状态、端口、切换命令和列表条目运行时状态；本次不改变这些状态机、端口绑定、配置字段或双击规则。

## 2. 目标与非目标

### 目标

1. 控制面板保持单行：左侧依次为“路由状态、全局代理、TUN 模式”，完全退出固定在同一行右侧。
2. 每个服务器列表项只保留一个与当前可操作代理角色相符的按钮：多代理模式下具有辅端口的条目操作辅代理，其他条目操作主代理。
3. 将主端口和辅端口的端口号、连接状态分开显示；用户文案统一为“辅端口”。辅端口仅在多代理模式且该条目配置了辅端口时显示。
4. 服务器列表项左侧信息明确分为两行：第一行从左到右为服务器名称与紧贴其右侧的延迟；第二行从左到右为服务器 IP、服务器端口和协议。延迟保留原有颜色、超时与未测试状态语义。
5. 服务器详情卡片在内容未溢出时紧贴网络延迟信息下方结束，且不显示滚动条；通过压缩卡片空白与主窗口可用高度避免默认内容溢出。

### 非目标

- 不改变主代理或辅代理的实际启动、停止、重载、端口释放与双击逻辑。
- 不改变 `settings.json`、`servers.json` 或运行时 Xray 配置结构。
- 不修改 Rust 更新器、发布流程、系统代理/TUN 行为或通知栏逻辑。

## 3. 变更清单

### [MODIFY]

- `Views/ControlPanelControl.xaml`：将状态行改为双端布局；左侧依次为路由状态、全局代理、TUN 模式，完全退出固定在同一行最右侧。
- `Views/ServerListControl.xaml`：把列表项右侧改为单一操作按钮与独立的端口状态行；在多代理+辅端口条目时显示辅代理操作，否则显示主代理操作；列表项左侧改为“名称与紧邻延迟”的第一行和“IP、端口、协议”的第二行。
- `Views/ServerListControl.xaml.cs`：提供单一操作按钮的显示文案、点击分派与主/辅端口状态文本格式化；复用既有命令，避免改变底层代理行为。
- `Views/ServerDetailControl.xaml`：详情卡片顶对齐，使底边跟随内容高度；移除详情卡片滚动容器，压缩多余留白并让详情区随内容自然结束。
- `_System/architecture/task_breakdown.md`、`_System/memory/current_state.md`：记录 WI-010 的这轮 UI 扩展和验收状态。
- `2026-09-07_xrayui_multi_proxy_reliability_and_experience_plan.md`：追加本方案与既有方案的关系及验收结果摘要。

### [NEW]

- 无。

### [DELETE]

- 从服务器列表项中移除主代理与辅代理同时出现的双按钮呈现；不删除任何命令、配置或兼容字段。

## 4. 实施与验收

1. 批准后创建并验证本轮变更前快照，更新本方案和 WI-010 为实施中。
2. 分别完成控制面板、服务器列表和服务器详情卡片的最小布局调整。
3. 使用带多条服务器及辅端口的原便携配置进行 Native AOT 启动回归，确认不重现多列表项闪退。
4. 运行 `dotnet test XrayUI.Tests/XrayUI.Tests.csproj -c Release`、win-x64 Native AOT 发布、Host Architecture Validation、Host Documentation Validation 和 `git diff --check`。
5. 在桌面烟雾测试中确认：控制项同一行，前三项在左、完全退出在右；每项仅一个操作按钮；主端口/辅端口状态及延迟位置正确；详情卡片无多余底部空白和滚动条。

## 6. 风险、回滚与决策

- 风险：服务器列表使用虚拟化 DataTemplate；不得重新引入跨作用域 `ElementName` 绑定，避免 Native AOT 在多个条目加载时退出。
- 风险：列表内容密度增加可能在窄窗口截断；沿用现有较宽窗口和列表列宽，并以文本截断而不是溢出处理超长节点名。
- 风险：移除详情滚动容器后，极端小窗口或异常长内容可能被裁切；以详情内容自然高度和现有窗口最小尺寸为基线验证，若仍无法完整容纳，将优先压缩卡片内部间距而不恢复滚动条。
- 回滚：恢复本轮快照中的四个视图与治理文档；不触碰用户 `Data/`。
- Decision Item：开发者已批准实施；不包含 Git 提交、推送或发布。

## 7. 实施结果

- 控制面板状态行已改为双端布局：路由状态、全局代理和 TUN 模式位于左侧，完全退出固定于同一行右侧。
- 服务器列表项已改为单一代理操作按钮；在多代理模式且有辅端口时操作辅代理，其他情形操作主代理。主端口总是显示配置端口与已连接/未连接状态；辅端口在适用时以“辅端口”显示相同状态。
- 列表左侧信息已收敛为两行：名称与延迟紧邻显示在第一行，IP、端口和协议在第二行。实现未使用跨作用域 `ElementName` 绑定。
- 服务器详情卡片已移除滚动容器、顶对齐并随内容高度结束，避免默认内容产生底部空白或滚动条。
- 自动验证：Release 构建成功；单元测试 97/97 通过（NuGet 漏洞源不可访问仅产生 NU1900 警告）；win-x64 Native AOT 发布后，使用原多节点便携配置持续启动 15 秒，无退出或应用崩溃事件。
- 待开发者桌面验收：确认窄/宽窗口下的文字截断、详情卡片无滚动条及整体视觉间距；此项完成前本方案保持 `in_progress`。

## 8. 后续范围内细调

- 辅代理条目不再显示主端口，仅显示辅端口；普通主代理条目保持仅显示主端口。
- 端口号与连接状态拆分为独立文本，间距增加；连接状态复用现有运行状态笔刷，已连接为绿色，未连接为灰色。
- 右侧主视图由剩余高度布局改为内容高度布局，详情卡片、设置按钮和路由状态控制区连续排列，移除中间无意义空白。
- 自动验证：本轮 Release 构建、97/97 单元测试和原多节点便携配置的 Native AOT 启动回归均通过；视觉烟雾测试仍待开发者确认。

## 9. 字号与默认窗口高度细调

- 服务器列表的延迟、IP、端口和协议字体调整为 16px，与服务器详情的主要信息字体一致；主/辅代理操作按钮调整为 16px 并扩大内边距。
- 主/辅端口与连接状态仍保持较小的辅助信息层级，避免与节点主体信息竞争。
- 默认完整窗口高度从 720 调整为 660，使窗口底边更接近设置、路由和完全退出控制行，同时保留详情卡片的无滚动展示空间。
- 自动验证：Release 构建无警告无错误，97/97 单元测试通过；原多节点便携配置 Native AOT 启动回归持续运行 15 秒，无退出或应用崩溃事件。视觉烟雾测试仍待开发者确认。
