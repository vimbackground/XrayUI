# XrayUI 残留核心端口恢复与操作按钮细调方案

## 1. 事实基线

- 主代理重新启用时，现有启动前检查最多等待本地端口 2 秒；仍不可用便直接显示改端口提示。
- 受管 Xray 核心正常停止时会杀掉已跟踪进程并等待退出，但在应用异常终止、进程跟踪丢失或退出延迟时，可能遗留同一便携版启动的 `xray.exe`。
- 当前端口检查只能判断“不可用”，不能归属占用进程，因此不能安全地区分本应用遗留核心与第三方程序。
- 服务器列表主/辅代理按钮当前为 16px；名称同为 16px，但按钮的较大内边距使其视觉上偏大。

## 2. 目标与非目标

### 目标

1. 主端口在常规等待后仍被占用时，仅自动清理可明确归属当前便携版的残留 Xray 核心，再等待端口释放并重新启动。
2. 真实第三方占用、无法识别归属或无法安全结束的进程，继续显示现有改端口提示，绝不自动结束。
3. 缩小列表操作按钮的视觉体积，使其与 16px 节点名称协调，同时保持主/辅代理状态颜色与现有状态语义。
4. 残留核心恢复前后保持所有辅代理状态不变：原已连接的辅代理继续连接，原未连接的辅代理继续未连接。

### 非目标

- 不按端口号结束任意未知进程，不结束其他目录、其他实例或其他代理软件的 `xray.exe`。
- 不改变端口配置、订阅、主/辅代理状态机、TUN 行为或用户 `Data`。
- 不因恢复主代理而启用、关闭、重置或重新分配任何辅代理端口。
- 不承诺消除内核网络栈的短暂端口释放延迟；清理后仍采用有限等待，失败时保留明确提示。

## 3. 界面与流程示意

```text
服务器列表操作区
┌─────────────────────────────────┐
│                      [启用主代理] │  ← 紧凑按钮，状态色随连接状态变化
│ 主端口 :9999        未连接        │
└─────────────────────────────────┘

主代理启动前
端口可用 ─────────────────────────────→ 启动
端口忙 → 等待 2 秒 → 当前便携版残留 Xray？
                            ├─ 是 → 结束残留 → 再等 2 秒 → 启动
                            └─ 否/失败 → 保留“修改端口”提示

恢复前：辅 A 已连接，辅 B 未连接
恢复后：辅 A 已连接，辅 B 未连接
```

## 4. 变更清单

### [MODIFY]

- `Helpers/PortHelper.cs`：补充仅查询目标 TCP 监听端口所有者 PID 的 Windows API 封装，以及规范化路径比较；查询失败时返回空，绝不猜测进程归属。
- `Services/XrayService.cs`：增加受限的残留核心恢复入口。仅结束同时满足“占用当前目标本地端口”且“可执行文件路径与当前捆绑 `xray.exe` 完全匹配”的进程；结束后限时等待退出并写入诊断日志。
- `ViewModels/ControlPanelViewModel.cs`：在常规 2 秒端口等待失败后调用残留核心恢复；恢复成功才进行第二次有限等待，仍失败或归属不明时显示原端口冲突提示。恢复重建时复用当前主代理和已持久化的辅代理启用状态，不改变任何辅代理状态。
- `Views/ServerListControl.xaml`：缩小按钮的内边距与视觉尺寸，保持节点名称为 16px；按钮状态色继续通过当前主/辅代理连接状态驱动。
- `Views/ServerListControl.xaml.cs`：若现有按钮主题无法直接表达状态色，提供仅基于已存在连接状态的安全显示映射，不改变操作分派。
- `XrayUI.Tests/PortHelperTests.cs` 或新增针对性测试文件：覆盖目标监听端口的 PID 查询及严格路径匹配；端口等待失败后只有受管恢复成功才进入第二次等待，未知进程不进入清理路径。
- `_System/architecture/task_breakdown.md`、`_System/memory/current_state.md` 与现有多代理可靠性方案：记录批准、实现、验证与剩余视觉验收。

### [NEW]

- 无；优先在 `XrayService` 内复用既有进程生命周期与日志能力。

### [DELETE]

- 无物理文件删除；仅替换端口冲突前的处理顺序。

## 5. 实施、验收、风险与回滚

1. 批准后创建并验证变更前快照，方案转为 `in_progress`。
2. 先实现可测试的受管进程归属判断与恢复结果，再接入启动前端口检查，最后调整按钮视觉。
3. 验收：端口可用时不触发清理；受管残留核心占用时自动恢复并启动；未知或第三方占用时不结束进程且仍显示端口提示；恢复前后所有辅代理的启用状态和端口配置完全一致。
4. 运行 Release 测试、win-x64 Native AOT 发布、原多节点便携配置启动回归、Host Architecture Validation、Host Documentation Validation 和 `git diff --check`。
5. 风险控制：进程路径或所占目标端口任一无法确认时默认不清理；所有结束操作限制在当前便携版受管核心，并记录到现有内存日志。
6. 回滚：通过本轮快照恢复 `XrayService`、`ControlPanelViewModel`、列表视图与治理文档；不触碰用户 `Data`。
7. Decision Item：开发者已批准实施；不包含 Git 提交、推送或发布。

## 6. 实施记录与自动验收

- 已实现：常规端口等待失败后，先用 Windows TCP 监听表取得目标端口所属 PID；只有该 PID 的可执行文件路径规范化后精确等于当前便携版捆绑 `xray.exe`，才结束该进程树。进程、端口或路径任一不明时不清理，继续原端口冲突提示。
- 已实现：恢复成功后才进行第二个最多 2 秒的端口释放等待；重新启动仍从 `GetAllServers()` 构建配置，因此不会改写主代理或任一辅代理的已连接状态、未连接状态或端口。
- 已实现：服务器行操作按钮收紧内边距，字体继续与节点名称同为 16px；按钮背景和边框随当前主/辅代理连接状态在现有绿色与灰色状态色之间切换。
- 自动验证：Release 构建无警告无错误；单元测试 99/99 通过，新增目标监听 PID 与严格路径匹配测试；win-x64 Native AOT 发布通过；将原多节点便携配置复制到隔离发布副本后运行 15 秒未退出；Host Architecture、Host Documentation 和 `git diff --check` 通过。
- 待桌面烟雾测试：用主代理“关闭后立刻启用”复现原端口占用，确认不会提示改端口；再确认已连接和未连接的辅代理在恢复前后分别保持原状态，并检查紧凑按钮颜色和大小。完成后可将方案改为 `verified`。
