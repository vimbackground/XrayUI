# XrayUI 多代理可靠性与交互改进方案

## 1. 事实基线

- XrayUI 当前以一个 `xray.exe` 进程同时承载主入站、主代理和全部已启用的独立端口入站及出站。
- 双击服务器会进入主连接切换路径；辅助连接现有开关通过重建配置并重启同一核心进程生效。
- `XrayService` 已等待旧核心退出，但端口可用性判断、连接切换、配置重载和退出清理分散在多个层次，尚缺少覆盖连续快速切换与端口释放竞态的统一会话状态模型和回归测试。
- 当前端口检查只能说明检查瞬间的 TCP/UDP 占用情况，不能单独证明占用者、旧核心释放进度或随后启动时仍可绑定。
- Xray 已输出启动信息和带入站、出站标签的访问日志；应用已有固定大小日志缓冲区和独立日志窗口，可以作为分代理动态信息窗口的基础。
- 服务器列表已支持双击和动态右键菜单，并在项目列表项右侧显示“专口”标识；底部控制面板仍提供全局启动或停止按钮。
- 主窗口关闭默认隐藏到通知区域；托盘图标由 `MainWindow` 创建，应用已有完全退出清理入口，但控制面板没有直接的完全退出按钮，也缺少资源管理器重启或图标丢失后的系统性恢复策略。
- 当前工作树在创建本方案前无未归因修改；现有状态为正常运行、等待新 Work Item。

## 2. 已确认的产品行为

1. 未开启多节点分流时，双击服务器执行主代理切换：串行停止旧会话、确认端口释放、启动目标服务器；正常切换不显示端口冲突。
2. 开启多节点分流时：
   - 未配置辅助端口的服务器仍按主代理切换处理。
   - 已配置辅助端口的服务器，双击只开关该辅助代理，不改变主代理及其他辅助代理的配置和界面状态。
   - 第一版允许底层单核心配置重载造成其他连接瞬时闪断，不改为每代理一个进程。
3. 术语统一为“主代理”和“辅助代理”，不再面向普通用户显示“独立端口分流”或“专口”。
4. 服务器详情区域增加动态信息入口；打开软件内独立窗口，以终端风格实时显示信息，默认查看主代理，并可切换到各辅助代理。
5. 控制面板增加“完全退出”；它停止代理、恢复相关系统网络状态、移除托盘资源并退出进程。关闭主窗口仍只隐藏到通知区域。
6. 托盘图标丢失时自动重建，包括 Windows Explorer 重启后的通知区域恢复。

## 3. 目标

- 消除正常主代理切换时由旧会话释放竞态引起的误报端口冲突，并在真实外部占用时给出可操作的诊断。
- 让主代理和辅助代理的开关含义、状态和入口在服务器列表中保持一致。
- 为普通用户提供可读状态，为排障提供可复制的原始动态日志，并能按主代理或辅助代理查看。
- 提供清晰可靠的完全退出路径，并提高长时间后台运行时托盘图标的自恢复能力。
- 以自动化测试锁定连接状态机、日志归类、端口诊断和退出生命周期的关键行为。

## 4. 非目标

- 不在本次改为主代理与每个辅助代理各自运行一个 `xray.exe` 的多进程架构。
- 不保证开关辅助代理时其他现存网络连接绝对零中断；单核心重载可能造成瞬时闪断。
- 不实现真正的 Windows 控制台进程；动态信息窗口是应用内终端风格窗口。
- 不改变订阅格式、节点协议、路由规则语义、数据目录的便携性或现有发布渠道。
- 不执行 Git 提交、推送、发布或外部 vHarness 同步。

## 5. Decision Item 裁决

| Decision Item | action | 理由 |
|---|---|---|
| 辅助代理是否采用独立进程 | defer | 第一版保留单核心架构，接受配置重载时其他连接瞬时闪断；多进程隔离另案评估。 |
| 动态信息窗口形态 | adopt | 使用应用内终端风格独立窗口，避免额外控制台进程并复用现有日志能力。 |
| 用户术语 | adopt | 主路径称“主代理”，额外端口路径称“辅助代理”。 |
| 底部全局启动或停止按钮 | relocate | 代理开关移到对应服务器列表项右侧；控制面板保留状态和设置入口，不保留造成歧义的第二套开关。 |
| 主窗口关闭行为 | preserve | 继续隐藏到通知区域；新增的“完全退出”才结束进程。 |

## 8. 验收标准

- 连续快速双击不同普通服务器时，操作严格串行；旧核心退出并释放本应用端口后再启动新核心，不出现由本应用旧进程造成的端口冲突提示。
- 端口确由其他进程占用时，应用仍阻止启动，明确说明冲突端口并提供可行处理方式；不得用无限等待掩盖真实冲突。
- 未开启多节点分流时，双击只切换主代理；开启后，普通服务器仍切换主代理，配置了辅助端口的服务器只切换自身辅助代理逻辑状态。
- 开关一个辅助代理后，主代理及其他辅助代理的配置和界面状态保持不变；允许单核心重载产生瞬时闪断，并在操作中显示重载状态。
- 服务器列表右侧能直接看出并操作“主代理”和“辅助代理 · 端口”；右键菜单可以设为主代理或辅助代理，旧技术术语不再出现在普通用户主流程。
- 动态信息窗口默认展示主代理，可切换所有已配置辅助代理；实时显示运行状态、本地端口、启动时间、最近错误和归类日志，并支持复制及清空。
- 无法可靠归属某个代理的核心日志明确显示为公共信息，不错误归到某台服务器；现有地址遮罩和日志级别设置继续生效。
- 点击“完全退出”后，全部代理核心结束、系统代理及 TUN 清理按现有安全路径执行、托盘图标移除且 XrayUI 进程退出；关闭主窗口仍只隐藏到托盘。
- 模拟 Explorer 重启或托盘重建消息后，图标能够恢复且菜单、单击和双击仍有效；多次重建不产生重复图标或重复事件。
- 新增定向测试通过；`dotnet test XrayUI.Tests/XrayUI.Tests.csproj -c Release` 通过。
- README 规定的 win-x64 Native AOT `dotnet publish` 通过，并对生成应用完成一次主代理切换、辅助代理开关、动态信息、完全退出及托盘恢复烟雾测试。
- Host Architecture Validation、Host Documentation Validation、适用 vHarness 测试和 `git diff --check` 通过。

## 9. 风险与控制

- 端口问题可能同时包含旧核心释放竞态、系统代理或 TUN 清理延迟及真实第三方占用；先以可观测状态和测试区分原因，不用固定长延时作为唯一修复。
- 单核心架构无法保证辅助代理开关对其他连接绝对无影响；界面明确显示短暂重载，完全隔离继续作为后续 Decision Item。
- Xray 日志并非每一行都包含可归类标签；只对证据明确的行分类，其他行进入公共核心信息，避免误导。
- 日志可能包含目标地址等隐私信息；沿用现有遮罩设置，默认限制内存缓冲，不新增隐式落盘。
- 托盘恢复处理不当可能造成重复图标或悬挂事件；创建、修改、删除和重建均设计为幂等，并以生命周期测试和人工烟雾测试验证。
- 完全退出涉及系统代理与 TUN 清理；复用现有退出路径并保持幂等，失败时记录诊断，不能静默跳过关键恢复。
- UI 调整可能影响窄窗口和触控目标；以现有列表布局为基础，并执行多尺寸与高 DPI 人工检查。

## 14. 已批准的后续交互调整

- 关闭多代理模式时，所有辅助代理自动关闭并保存；列表隐藏辅助端口和辅助代理按钮，只保留主代理操作。重新开启模式后才恢复辅助代理相关控件，辅助代理保持关闭，等待用户明确启动。
- 服务器行将主端口、辅助端口与操作按钮分开显示：主代理按钮为“启用主代理”或“关闭主代理”，辅助代理按钮为“启动辅代理”或“关闭辅代理”。默认窗口及服务器列表列宽同步增大。
- 完全退出移至服务器详情下方左对齐；软件设置和个性化设置页均增加右上角“返回控制台”，移除标题栏中位置不直观的返回按钮。
- 这轮调整仍需在可交互 Windows 桌面执行视觉及行为烟雾测试；自动编译和单元测试通过不替代该检查。

## 15. 严重回归修复

- 发布内容不再包含 `Data/`。该目录是用户便携配置，不属于应用载荷；此前构建环境存在 `Data/` 时，增量发布物会把它带入覆盖安装目录，存在覆盖用户配置的风险。
- Rust 更新器在复制更新文件时，防御性跳过首级为 `Data/` 的文件；即使异常发布包包含用户数据，也不会覆盖安装目录内的现有配置。
- 设置或服务器 JSON 无法解析时，应用将原文件改名为带时间戳的 `.invalid-*.json` 备份并以空配置启动，而不是要求用户手动删除数据。启动初始化另有最终异常边界，避免 WinExe 静默闪退。
- 从分享链接或订阅文本导入时，只保存协议、主机和端口完整且端口在合法范围内的节点，拒绝可能生成无效配置的条目。
- 完全退出恢复到路由状态与 TUN 开关同一行。
